# README Writer

프로젝트 저장소를 이해하기 쉽게 만들어 주는 README.md 초안을 작성한다.

핵심 철학은 하나다. **좋은 README는 멋진 소개문이 아니라, 저장소에 실제로 존재하는 사실을 빠짐없이 정리한 문서다.** 방문자(채용 담당자, 협업 후보자, 미래의 나)가 "이게 무슨 프로젝트고, 어떻게 실행하고, 어디부터 보면 되는지"를 몇 초 안에 파악할 수 있으면 성공이다. 길이가 길다고 좋은 게 아니다.

이 스킬은 **Claude Code 환경**을 전제로 한다. 즉 저장소 파일 시스템과 셸에 항상 접근할 수 있다. 사람이 정보를 불러 줄 때까지 기다리지 말고, 도구로 저장소를 직접 읽어 근거를 확보하는 것이 이 스킬의 핵심이다.

## 절대 어기면 안 되는 원칙

이 세 가지는 README의 신뢰도를 좌우하기 때문에 특히 조심한다. AI가 만든 초안이 실무에서 버려지는 이유가 대부분 여기서 나온다.

1. **없는 기능을 지어내지 않는다.** 예시 데이터, 배포 링크, 테스트 명령, Docker 지원, CI 배지 같은 항목은 흔한 README 템플릿에 으레 들어가기 때문에 무심코 채워 넣기 쉽다. 저장소에서 근거를 찾지 못한 항목은 넣지 말고, 애매하면 사용자에게 물어본다. "그럴듯한데 실제로는 안 돌아가는 README"가 가장 나쁘다.

2. **과장하지 않는다.** "혁신적인", "강력한", "완벽한", "최고의" 같은 표현은 README에서 오히려 신뢰를 떨어뜨린다. README는 광고 문구가 아니라 사용 안내서에 가깝다. 소개는 짧고 사실 중심으로 두고, 자세한 내용은 기능 섹션에서 담담하게 설명한다.

3. **실행 명령은 실제 근거에서 가져온다.** 설치·실행 명령은 상상해서 쓰지 말고 `package.json`의 scripts, `Makefile`, `requirements.txt`, 실행 스크립트 등 실제 파일에서 확인해서 옮긴다. 확인할 수 없으면 그 자리에 `<!-- 확인 필요 -->` 같은 표시를 남기고 사용자에게 알린다.

## 작업 순서

### 0단계 — 기존 README가 있으면 먼저 읽는다

작업 전에 `Glob`으로 저장소에 `README.md`(또는 `README.rst`, `docs/README.md` 등)가 있는지 확인하고, 있으면 `Read`로 먼저 읽는다. 처음부터 다시 쓰지 않는다. 사용자가 직접 작성한 배지, 스크린샷, 데모 링크, 고유한 문구는 그 사람의 의도가 담긴 자산이므로 보존한다. 이 스킬의 역할은 그 위에서 (1) 근거 없는 항목을 찾아 교정하고, (2) 빠진 표준 섹션을 채우고, (3) 실제 저장소 상태와 어긋난 부분(바뀐 명령, 삭제된 기능 등)을 갱신하는 것이다. 기존 내용을 크게 삭제해야 할 때는 삭제 전에 사용자에게 이유와 함께 확인받는다.

### 1단계 — 저장소에서 사실부터 모은다

초안 품질은 입력 정보의 양과 정확도에서 갈린다. README를 쓰기 전에 도구로 저장소를 직접 읽어 근거를 확보한다. `Glob`으로 파일을 찾고, `Read`로 내용을 확인하고, 텍스트를 넓게 훑어야 하면 `Grep`을 쓴다.

우선적으로 확인할 것:

- **프로젝트 정체성**: 최상위 폴더 구조, 진입점 파일, 기존 문서·주석. 무엇을 하는 프로젝트인지 한 줄로 정리할 수 있어야 한다.
- **언어·런타임·의존성**: `package.json`, `requirements.txt`, `pyproject.toml`, `pom.xml`, `build.gradle`, `go.mod`, `Cargo.toml`, `Gemfile` 등. 언어 버전과 설치 명령의 근거가 된다.
- **실행 방법**: `scripts`(package.json), `Makefile`, `Dockerfile`, `docker-compose.yml`, 셸/배치 스크립트, 프레임워크 실행 명령.
- **환경 변수·설정**: `.env.example`, `config` 파일, 설정 관련 코드. 실제로 필요한 키만 추린다.
- **폴더 구조**: 방문자가 어디부터 보면 되는지 안내할 수 있도록 주요 디렉터리의 역할을 파악한다.

셸(`Bash` 도구)로 부작용 없는 확인을 직접 실행해 근거를 굳힌다:

- 클론 URL은 `git remote get-url origin`으로 확인해서 템플릿의 자리표시자 대신 실제 값을 채운다. 리모트가 없으면 자리표시자를 유지한다.
- 라이선스 섹션은 `LICENSE`/`LICENSE.md` 파일이 존재할 때만 넣고, 파일 내용에서 라이선스 종류를 확인한다.
- CI 배지나 테스트 언급은 `.github/workflows/` 같은 실제 설정이 있을 때만 한다.
- 명령 검증이 필요하면 부작용 없는 확인만 실행한다(런타임 버전 확인, 도구의 `--help` 출력 등). 빌드·배포·DB 마이그레이션처럼 상태를 바꾸는 명령은 함부로 실행하지 말고, 파일 근거로만 확인한 뒤 사용자에게 직접 돌려보길 권한다.

저장소를 다 읽고도 사실만으로 채울 수 없는 빈칸이 남으면(예: 프로젝트의 목적이 코드만으로 불분명하거나, 지원/예정/실험 기능의 경계가 애매할 때) 흔한 예시로 메우지 말고 `AskUserQuestion`으로 꼭 필요한 것만 묻는다. 대표적으로:

- 이 프로젝트를 한 줄로 설명하면? (예: 할 일 관리 웹앱 / 로그 분석 스크립트 / 블로그 글 자동화 도구)
- 지원하는 기능 / 아직 안 된 기능 / 실험 중인 기능은 각각 무엇인지?

### 2단계 — 표준 구조로 초안을 작성한다

아래는 실무에서 널리 쓰이는 기본 골격이다. 프로젝트에 해당하지 않는 섹션은 억지로 채우지 말고 **뺀다**. (예: 환경 변수가 없으면 설정 섹션을 생략한다.) 같은 스킬 폴더의 `assets/README_template.md`에 바로 채워 쓸 수 있는 템플릿이 있으니 `Read`로 열어 참고한다. (플러그인으로 설치된 경우 경로는 `${CLAUDE_PLUGIN_ROOT}/skills/readme-writer/assets/README_template.md`.)

1. **프로젝트 소개** — 해결하려는 문제와 대상 사용자를 한두 문단으로. 소개가 길어지면 정작 중요한 실행 방법이 아래로 밀린다. 짧게 끝낸다.
2. **빠른 시작 (Quick Start)** — 클론 → 의존성 설치 → 실행을 순서대로. 초보 개발자가 이 섹션만 보고도 실행할 수 있어야 한다. 설치 단계와 실행 예시는 분리해서 적는다.
3. **주요 기능** — 기능 이름만 나열하지 말고 "사용자가 실제로 얻는 결과" 중심으로. 예: "게시글 초안 생성", "파일 기반 입력 처리", "자동화 로그 기록". 구현 상태가 갈리면 지원/예정/실험 중을 구분해 정직하게 표시한다.
4. **설정과 주의사항** — 환경 변수, API 키, 운영체제 차이(예: Windows/Unix 경로·명령 차이), 알려진 제한 사항. 반복해서 나올 질문을 여기 모아 두면 나중이 편하다.

폴더 구조, 라이선스, 기여 방법 등은 프로젝트에 실제 근거가 있을 때만 추가한다.

### 3단계 — 검증하고 군더더기를 덜어낸다

초안을 넘기기 전에 스스로 점검한다:

- 각 기능·명령·항목이 저장소의 실제 근거와 연결되는가? 근거 없는 항목은 삭제하거나 `<!-- 확인 필요 -->`로 표시했는가?
- 과장 형용사("혁신적", "강력한", "완벽한")가 남아 있지 않은가?
- 설치·실행 명령이 실제 파일과 일치하는가?
- 소개가 실행 방법보다 무겁지 않은가?

마지막으로, 확실히 검증하지 못한 부분(특히 설치·실행 명령)은 사용자에게 짚어 준다. "이 명령들은 실제로 한 번 돌려서 확인해 보시길 권합니다" 같은 안내는 초안을 안전하게 쓰는 데 도움이 된다.

## 출력 형식

- 저장소 루트의 `README.md`를 `Write`(신규) 또는 `Edit`(기존 갱신)로 **파일에 직접 쓴다.** 채팅 창에 마크다운 텍스트만 뿌리고 끝내지 않는다. 작성 후에는 무엇을 새로 채웠고 무엇을 `<!-- 확인 필요 -->`로 남겼는지 요약해 알려 준다.
- README 본문 언어는 프로젝트 성격과 사용자 선호를 따른다. 지정이 없으면 사용자가 대화에서 쓰는 언어에 맞춘다.
- 코드·명령 블록에는 언어를 명시한 코드 펜스(bash, json, python 등)를 사용한다.

## 참고

- `assets/README_template.md` — 섹션별 채우기 가이드가 포함된 기본 템플릿. 새 초안을 시작할 때 `Read`로 열어 복사해서 사용한다.
