# 질문 답변 (Ask)

현재 코드베이스에 대한 질문을 받아 **실제 코드에서 확인한 근거**로 답변하는 읽기 전용 Q&A. 질문 하나에 답하고 끝나는 것이 목적이며, 수정 작업의 사전 단계가 아니다.

## 원칙

- **코드를 수정하지 않는다.** 답변이 수정 요청으로 이어지면 해당 절차 스킬(`dev-pack:feature-development`·`dev-pack:feature-change`·`dev-pack:bug-fix`·`dev-pack:refactoring`)로 전환한다.
- **추측 대신 근거.** 기억이나 그럴듯함으로 답하지 않고, 도구로 실제 코드를 확인한 내용만 단정한다.
- **질문 하나에 답하고 끝낸다.** 수정을 전제로 전체 지도를 그리는 탐색(영향도 분석·온보딩)은 `dev-pack:codebase-exploration` 절차를 따른다.

## 절차

1. **질문 이해** — 대상 기능·파일이 특정되지 않거나 해석이 여러 갈래로 갈리면, 추측으로 진행하지 말고 AskUserQuestion으로 선택지를 제시해 의도를 먼저 좁힌다. 질문이 명확하면 바로 2단계로 간다.
2. **근거 수집** — `dev-pack:codebase-exploration`의 도구 활용 방식대로 Grep/Glob으로 진입점과 심볼의 정의·참조를 좁히고, 해당 부분만 Read로 정독한다. 외부 라이브러리 동작이 얽히면 context7로 현재 문서를 확인한다. 여러 디렉터리·명명 규칙을 넓게 훑어야 하면 읽기 전용 `Explore` 에이전트에 위임해 결론만 받는다.
3. **답변** — 결론을 먼저 말하고, 근거를 `file_path:line` 클릭 가능한 형식으로 붙인다. 코드에서 확인하지 못한 부분이나 코드만으로 판단할 수 없는 부분(런타임 동작, 외부 설정 등)은 그렇다고 명시한다.
